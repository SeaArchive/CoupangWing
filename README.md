# CoupangWing

쿠팡 판매자 주문 ↔ Google Sheets 연동 웹사이트입니다. **이메일·비밀번호로 로그인**하고, 계정별 연결 정보와 작업 로그를 관리합니다. 자동 연동 시작 버튼을 누르면 서버가 정해진 간격으로 실행합니다. 브라우저를 닫아도 서버가 켜져 있으면 작업이 계속됩니다.

## 구성

- Node.js 24의 HTTP 서버와 SQLite. 설치할 npm 패키지가 없습니다.
- 이메일·비밀번호 회원가입/로그인, scrypt 비밀번호 해시, 서버 세션, CSRF 검사.
- 계정별 쿠팡 API 키·업체코드·Google 서비스 계정 키를 AES-256-GCM으로 암호화 저장.
- 계정별 시트 ID·탭·범위·실행 간격, 별도 자동 실행과 로그.
- PlutoArchive 현재 색상 `#000817`, 실버 `#c8cbcb`, 텍스트 `#edfffe`. 직선과 명확한 구분 중심.
- 기본은 데모 모드입니다. 데모는 외부 API를 호출하지 않으며 가짜 주문을 실제 통계에 넣지 않습니다.

## 실행

1. Node.js **24.x**를 설치합니다.
2. `.env.example`을 `.env`로 복사합니다.
3. `npm start`를 실행합니다.
4. `http://localhost:3000`에서 이메일로 계정을 만들고 로그인합니다.
5. **연동 설정**에서 쿠팡 업체코드, Access Key, Secret Key, Google 서비스 계정 JSON, 시트 ID와 탭 이름을 입력합니다.
6. Google 서비스 계정 이메일을 대상 시트의 **편집자**로 공유합니다. 각 사용자에게 별도의 서비스 계정을 사용하는 것을 권장합니다. Google Cloud 프로젝트에서 Google Sheets API를 활성화하세요.
7. 시트 형식과 서버 IP 등록을 확인한 뒤 실행 모드를 **실제 연동**으로 바꾸고 설정을 저장합니다.
8. **지금 한 번 실행**하여 실제 주문 한 건을 확인하고 **자동 연동 시작**을 누릅니다.

쿠팡 및 Google의 비밀키를 GitHub에 커밋하거나 로그에 입력하지 마세요. 저장된 키는 브라우저로 다시 반환하지 않으며, 설정 화면의 비밀키 입력칸을 비워 저장하면 기존 키가 유지됩니다. 업체코드 변경 시 API 키와 전용 탭도 같이 확인하세요.

## 기본 시트 형식

55행부터 기록합니다. 헤더와 1~54행은 건드리지 않습니다. 값 API만 사용하므로 공급자의 색상·글꼴·셀 서식을 변경하지 않습니다.

| 열 | 내용 | 동작 |
|---|---|---|
| A~L | 주문접수일, 시트작성일, 수취인명, 우편번호, 수취인주소, 전화번호1, 전화번호2, 품목명, 수량, 배송메세지, 규격, 보내는분 성명 | 쿠팡 주문으로 갱신 |
| M | 주문 상태 | 주문접수 / 배송대기 / 배송지시 / 배송중 / 배송완료 / 직접배송 |
| N~Z | 발송날짜, 택배사, 운송장번호, 수취인명, 전화번호, 품목명, 수량, 규격, 도도매 원가, 위탁 원가, 위탁 원가 총액, 포장배송비, 보내는분 성명 | 공급자 입력을 유지 |
| O, P | 택배사, 운송장번호 | 쿠팡 등록 대상으로 읽음 |
| AA | 연동 식별키 | 주문과 송장의 정확한 연결용. 숨겨도 되지만 수정/삭제하지 마세요. |

- 새 주문은 관리 범위의 마지막 사용 행 다음에 기록합니다. 기존 주문은 AA 식별키로 찾아 갱신합니다. A~L의 API 값이 비어 있으면 빈칸으로 기록합니다. 시트작성일은 최초 기록 시각을 유지합니다.
- N~Z에 누락된 값은 채우거나 지우지 않습니다. O/P가 비어 있는 행은 송장 전송에서 제외합니다.
- 행 정렬은 **A~AA 전체를 함께** 정렬해야 합니다. AA 없이 다른 열만 정렬하면 식별키와 공급자 입력이 분리될 수 있습니다.
- 날짜는 한국 시각. 주문접수일은 결제일시를 사용합니다. 보내는분 성명은 계정 설정을 우선하고 미입력 시 쿠팡 판매자명입니다. 실제 전화번호가 제공되지 않으면 전화번호2는 빈칸입니다.
- CJ대한통운, 한진택배, 롯데택배, 로젠택배, 우체국 등 주요 택배사 이름을 쿠팡 코드로 변환합니다. 다른 택배사는 공식 택배사 코드를 넣으세요. 운송장번호는 텍스트 형식으로 입력해 앞자리 0을 보존하세요.
- 글자와 셀 색상은 무시합니다. 운송장 읽기 범위와 각 열은 설정 화면에서 변경할 수 있습니다.

## 자동 처리 범위

최근 7일(설정 가능, 1~30일)의 주문을 상태별로 조회하고, 현재 주문 정보로 A~M을 갱신합니다. 상품 하나당 한 행입니다. 동일 묶음배송번호의 모든 상품에 같은 택배사·운송장번호가 있어야 한 번에 등록됩니다.

송장 등록은 **상품준비중(INSTRUCT)**에서만 가능합니다. 결제완료 주문의 상품준비중 전환은 현재 쿠팡 Wing에서 수행합니다. 분리배송, 기존 송장 수정, 반품·교환 자동처리 및 완전 취소 주문의 동기화는 현재 지원하지 않습니다. 주문조회 기간 밖의 오래된 주문은 M열이 자동으로 최신화되지 않을 수 있으므로 조회 기간을 조정하세요.

송장 등록 직전 단건 조회로 상품 구성과 수취인·수량을 다시 확인합니다. 요청 전 DB에 `확인필요`를 기록하고, 통신 끊김이나 부분실패가 발생하면 무조건 재전송하지 않습니다. 다음 주기에 같은 송장이 쿠팡에 있는지 확인해 등록 완료로 정리합니다. 계속 확인필요라면 쿠팡 Wing에서 실제 등록 여부를 검토해야 합니다.

## 서버 배포

**GitHub 저장소/Pages만으로는 서버 작업을 실행할 수 없습니다.** 장시간 실행되는 Node 서버가 필요합니다. Dockerfile과 Render Blueprint(`render.yaml`)를 포함했습니다. Render 배포는 유료 Starter 및 1GB 영속 디스크를 사용하도록 명시했습니다. 다른 VPS/서버에서도 실행할 수 있습니다.

운영 환경에는 다음을 설정하세요.

- `NODE_ENV=production`, `HOST=0.0.0.0`
- `APP_ORIGIN=https://실제-사이트-주소` (끝의 `/` 없음), `COOKIE_SECURE=true`
- `ENCRYPTION_KEY`: `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"`로 생성한 값. 반드시 안전하게 백업하세요. 변경하면 기존 키를 복호화할 수 없습니다.
- `DATA_DIR`: 영속 디스크 경로. SQLite와 암호화된 계정 설정·로그·송장 원장을 유지합니다.
- `ALLOW_REGISTRATION=false`: 필요한 계정을 만든 후 신규 가입을 닫고 싶을 때 사용합니다.

쿠팡에는 **집 IP가 아니라 API를 호출하는 배포 서버의 외부 IP**를 등록해야 합니다. 선택한 호스팅의 outbound IP 안내에서 확인하세요. IP가 변하는 호스팅은 고정 외부 IP 또는 고정 IP 프록시가 필요합니다. 서버를 여러 개 복제하는 배포는 지원하지 않습니다. 단일 인스턴스로 실행하세요.

Render의 기본 outbound IP는 공유 CIDR 범위이므로, Blueprint만 배포했다고 쿠팡 IP 등록까지 해결되는 것은 아닙니다. 쿠팡에서 허용하는 IP 등록 방식과 맞는지 확인하고, 필요하면 고정 공인 IP가 있는 VPS 또는 별도 고정 egress를 사용하세요.

현재 로그인은 이메일 주소와 비밀번호입니다. 이메일 소유 확인, 비밀번호 재설정 메일 및 소셜 로그인은 포함하지 않았습니다. 필요하면 다음 단계에서 메일 제공자와 연결할 수 있습니다.

## 검증

`npm test`로 계정 격리, 인증/CSRF, 암호화, 숫자 식별자 정밀도, 시트 보존, 중복 수집, 송장 중복 방지, 불확실한 응답을 검증합니다. 실제 고객 데이터 없이 모의 제공자를 사용합니다. 운영 전 실제 계정의 읽기·쓰기·송장 등록 확인은 별도로 필요합니다.
